# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Developers, engineering teams, technical leaders, platform engineers, reviewers, and existing or prospective GitHub Copilot users evaluating a four-part learning series.

## Product Purpose

Provide a professional guide to the GitHub Copilot Back to School Series 2026, preserving the full session information from the supplied PDF and making it easy to choose a relevant session and register for either available time.

Success means visitors can quickly understand the progression of the series, identify the right sessions for their experience and role, and reach the correct registration link.

## Positioning

The site presents the series as a practical, demo-focused learning journey from everyday Copilot use through agentic development and AI-native software delivery, rather than as a generic events listing.

## Operating Context

Visitors may arrive from a shared link, review the page independently or with an engineering team, compare four consecutive Wednesday sessions, and register for either a 10:00 BST or 16:00 BST event.

## Capabilities and Constraints

- Static site suitable for GitHub Pages.
- All factual series content and registration destinations originate from the supplied PDF.
- Registration URLs must remain easy to replace with future `gh.io` short links.
- The site should work well across desktop and mobile browsers.
- No attendee counts, customer claims, testimonials, or other proof should be invented.

## Brand Commitments

- Name: GitHub Copilot Back to School Series 2026.
- Professional GitHub Copilot-inspired presentation, using the GitHub Copilot feature page as a craft reference without copying it.
- Practical, confident, developer-focused voice.

## Product Principles

- Make the full series understandable before asking visitors to register.
- Preserve detail while creating a clear path through the four-session progression.
- Keep registration choices visible, explicit, and easy to update.
- Demonstrate modern developer workflow concepts through the page experience itself.
- Maintain credibility by using only supplied facts.

## Accessibility & Inclusion

Use semantic HTML, keyboard-accessible controls, visible focus states, sufficient contrast, reduced-motion support, and responsive layouts.
